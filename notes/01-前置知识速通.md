## ① jsoncpp — 数据的格式

### 两个核心操作

```
序列化：  C++ 对象  ──→  JSON 字符串    (发送给 AI API)
反序列化：JSON 字符串 ──→  C++ 对象     (解析 AI API 返回)
```

### 五大工具

| 类/函数 | 角色 | 项目位置 |
|---------|------|---------|
| `Json::Value` | 万能容器（对象/数组/数字/字符串/布尔/null） | 全部 .cpp |
| `StreamWriterBuilder + writeString` | 序列化 | Provider 构造请求体 |
| `CharReaderBuilder + parseFromStream` | 反序列化 | Provider 解析响应 |
| `valueToQuotedString` | SSE 安全编码 | ChatServer 流式响应 |

### 项目实例：构造请求体

```cpp
// ChatGPTProvider::sendMessage() 实际代码
Json::Value messagesArray(Json::arrayValue);
for (const auto& msg : messages) {
    Json::Value obj(Json::objectValue);
    obj["role"] = msg._role;
    obj["content"] = msg._content;
    messagesArray.append(obj);
}

Json::Value requestBody;
requestBody["model"] = "gpt-4o-mini";
requestBody["input"] = messagesArray;
requestBody["temperature"] = 0.7;

Json::StreamWriterBuilder writer;
writer["indentation"] = "";
std::string body = Json::writeString(writer, requestBody);
// → {"model":"gpt-4o-mini","input":[...],"temperature":0.7}
```

### 项目实例：解析响应

```cpp
// 反序列化 AI 返回的 JSON
Json::Value responseJson;
Json::CharReaderBuilder reader;
std::string errors;
std::istringstream stream(response->body);
Json::parseFromStream(reader, stream, &responseJson, &errors);

// ChatGPT 响应路径: output[0].content[0].text
std::string reply = responseJson["output"][0]["content"][0]["text"].asString();

// DeepSeek 响应路径: choices[0].message.content
std::string reply = responseJson["choices"][0]["message"]["content"].asString();
```

### SSE 安全编码

```cpp
// ChatServer: 防止 AI 返回的文本破坏 SSE 格式
std::string sseData = "data: " + Json::valueToQuotedString(chunk.c_str()) + "\n\n";
// "data: \"换行\\n会被转义\"\n\n"  ← 安全！
```

## ② httplib — 数据的传输

### 双重角色

| 角色 | 类 | 位置 | 目标 |
|------|-----|------|------|
| Client | `httplib::Client` | ChatGPTProvider.cpp | 向 AI API 发 HTTPS |
| Server | `httplib::Server` | ChatServer.cpp | 接收浏览器请求 |

### 同步 POST（全量返回）

```cpp
httplib::Client client("https://api.deepseek.com");
client.set_connection_timeout(30, 0);
client.set_read_timeout(60, 0);

httplib::Headers headers = {
    {"Authorization", "Bearer " + _apiKey},
    {"Content-Type", "application/json"}
};

auto response = client.Post("/v1/chat/completions", headers, body, "application/json");
if (response && response->status == 200) {
    std::string reply = response->body;  // 完整 JSON
}
```

### 流式 POST（SSE 增量返回）

```cpp
// 手动构造请求 + 设置 content_receiver 回调
httplib::Request req;
req.method = "POST";
req.path = "/v1/chat/completions";
req.body = requestBodyStr;

req.content_receiver = [&](const char* data, size_t len, size_t offset, size_t total) {
    buffer.append(data, len);  // 追加到缓冲区
    // SSE 解析...
    return true;  // 继续接收
};

auto result = client.send(req);  // 阻塞直到连接关闭
```

## ③ SSE 协议 — 流式响应格式

### 协议格式

```
event: response.output_text.delta\n
data: {"delta":"大"}\n
\n                          ← 两个 \n 是事件分隔符
```

| 行前缀 | 含义 |
|--------|------|
| `data:` | 数据行 |
| `event:` | 事件类型（可选） |
| `:` | 注释行（心跳） |
| 空行 | 事件结束 |

### TCP 分包容错

```cpp
std::string buffer;

// content_receiver 每来一块数据就调用
buffer.append(data, dataLength);

// 循环查找完整事件
size_t pos = 0;
while ((pos = buffer.find("\n\n")) != std::string::npos) {
    std::string event = buffer.substr(0, pos);  // 完整事件
    buffer.erase(0, pos + 2);                    // 删除已处理
    
    // 解析 data: 行 → JSON 解析 → callback(delta, false)
}
```

### 四个 Provider SSE 格式差异

| Provider | 事件类型 | 结束标记 | 分隔符 |
|----------|---------|---------|:---:|
| ChatGPT | `event:` + `data:` | `response.completed` | `\n\n` |
| DeepSeek | 只有 `data:` | `[DONE]` | `\n\n` |
| Gemini | 只有 `data:` | `[DONE]` | `\n\n` |
| Ollama | 每行完整 JSON | `{"done":true}` | 单个 `\n` |

## ④ fmt — 格式化引擎

### 在项目中的角色

不被直接 `#include`，但 spdlog 的所有 `{}` 占位符都依赖它：

```
INFO("model {} init", name)
  → spdlog::logger::info()
    → fmt::format("model {} init", name)
      → "model gpt-4o-mini init"
```

### 和 spdlog 的关系

```
spdlog 管：写到哪里、多线程安全、异步写入
fmt 管：  把 "xxx {} xxx" 中的 {} 替换成实际值
```

### 为什么拼 JSON 用 ostringstream 而不是 fmt

JSON 花括号太多，fmt 需要把每个 `{` 写成 `{{`：

```cpp
// 用 fmt（花括号地狱）
fmt::format(R"({{"model":"{}"}})", name);  // 难以阅读

// 用 ostringstream（清晰）
ostringstream os;
os << R"({"model":")" << name << R"("})";
```

## ⑤ spdlog — 日志系统

### 六层级别

```
TRACE < DEBUG < INFO < WARN < ERROR < CRITICAL
(开发)  (调试)   (正常)  (警告)  (错误)   (致命)
```

### 项目封装：单例 + 宏

```cpp
// myLog.h: 6 个宏，自动附加文件名和行号
#define INFO(format, ...)  Logger::getLogger()->info(
    "[{:>10s}:{:<4d}]" format, __FILE__, __LINE__, ##__VA_ARGS__)

// 使用
INFO("model {} init successed", name);
// → [16:23:47][ChatServer][info   ][ChatSDK.cpp:109 ]model gpt-4o-mini init successed
```

### 异步日志

```cpp
spdlog::init_thread_pool(32768, 1);  // 队列 32768 条，1 个后台线程
spdlog::flush_on(logLevel);           // ≥ logLevel 立即刷新
```

### 两个初始化入口

| 入口 | 输出目标 | 级别 |
|------|---------|------|
| ChatServer (main.cpp) | `"stdout"` 控制台 | 命令行 `--log_level` |
| testLLM.cpp | `"test_log.txt"` 文件 | `debug` |

## ⑥ gflags — 命令行参数

### 三步使用

```cpp
// ① 定义
DEFINE_int32(port, 8080, "端口号");

// ② 解析
gflags::ParseCommandLineFlags(&argc, &argv, true);

// ③ 使用
config.port = FLAGS_port;  // ./AIChatServer --port=9000 → FLAGS_port=9000
```

### 参数优先级

```
默认值 (8080)  <  配置文件 (ChatServer.conf)  <  命令行 (--port=9000)
```

### API Key 为什么用环境变量？

```cpp
config.chatGPTAPIKey = getEnvVar("chatgpt_apikey");  // 从 bashrc 读取
// 不用 gflags → 不会泄露到 Git 仓库
```
